Run one disposable tapstate data path without installing the CLI or preparing
your own databases. The playground captures MySQL orders and PostgreSQL
shipments, assembles them into one order document, and materializes the result
in MongoDB.

When you finish, you will have a running `order_pipeline`, a checked initial
result in MongoDB, and a web session for exploring the pipeline.

This quickstart is an evaluation environment, not a server installation or
production deployment. Use sample data only. The playground tracks the latest
pinned CLI and server release (`0.8.0`); for manual self-hosted installation,
use [Initialize storage](/docs/guides/bootstrap-and-auth#initialize-storage).

## Why assemble this state

The sample keeps order details in MySQL and fulfillment records in PostgreSQL.
Neither database can join a table in the other, so an application that needs a
complete order would otherwise query both systems and assemble the result on
every request.

Tapstate declares that relationship once. An initial snapshot builds the
current order state, and CDC keeps the same object fresh when either the order
or one of its shipments changes.

## Before you begin

You need:

- macOS or Linux;
- Docker with the Compose plugin running;
- `curl`;
- several GB of free Docker storage.

Confirm Docker is available:

```bash
docker info
docker compose version
```

You do not need to [install the tapstate CLI](/docs/overview/install). The
script downloads the tools, connector artifacts, and the
Quickstart stack into a disposable `tapstate-demo` directory. The published CLI
and server assets are selected from the same release path.

## 1. Start the playground

Run the published quickstart script:

```bash
curl -fsSL https://install.tapstate.dev/demo | sh
```

The script starts MySQL, PostgreSQL, MongoDB, and a tapstate server. It then:

1. prepares the MongoDB connector and initializes storage;
2. asks you to choose an administrator username and password, then registers the source connectors;
3. applies and discovers both source connections;
4. applies and starts `order_pipeline`;
5. waits for the assembled initial state.

The command can take several minutes the first time while Docker downloads the
images.

Enter the administrator credentials at the terminal prompts. Press Enter at
`Administrator username [admin]:` to use `admin`, or enter another username.
You must supply a password; there is no default password. It is hidden as you
type and is not saved in `.env`. Keep the credentials for browser
and CLI sign-in; when rerunning against existing volumes, use the existing
administrator account. For non-interactive runs, supply `TAPSTATE_ADMIN_USER`
and `TAPSTATE_ADMIN_PASSWORD` through your environment's secret mechanism.
Do not put passwords in command arguments or committed scripts.

For an unreliable connection, save the script before running it so you can inspect and rerun the same file:

```bash
mkdir -p tapstate-demo
cd tapstate-demo
curl -fL https://install.tapstate.dev/demo -o quickstart.sh
sh quickstart.sh
```

The script retries interrupted asset downloads and keeps an incomplete transfer
as a `.part` file. Run the same command again to resume it. A failed transfer
does not count as a successful setup.

## 2. Confirm the result

A successful run ends with this line:

```text
quickstart: 5 orders from MySQL, each carrying its shipments from PostgreSQL -- 6 of them, in one object per order
```

The order and embedded-shipment counts are the quickstart's success condition.

If a setup command fails, the script prints the CLI diagnostic and exits. It does not continue to the snapshot check or report an empty target as success.

## 3. Open the web application

On the Docker host, open `http://127.0.0.1:8080` in your browser. The Playground
binds that port to the host's loopback interface. From another computer, keep
this SSH tunnel open and visit `http://127.0.0.1:18080` locally:

```bash
ssh -N -L 127.0.0.1:18080:127.0.0.1:8080 user@linux-host
```

Replace `user@linux-host` with your SSH login for the Docker host.

Sign in with the administrator username and password you set during setup.
If you accepted the default username at the terminal prompt, use `admin`.
For a non-interactive installation, use the credentials supplied through
`TAPSTATE_ADMIN_USER` and `TAPSTATE_ADMIN_PASSWORD`.

The sample is already configured and running. You do not need to create a
connection, author a workspace, or start another pipeline to complete this
quickstart.

Under **Data Sources**, open `orders_db` and select `orders` to inspect its
discovered columns. `fulfillment_db` contains the `shipments` table.

In **Pipelines**, open `order_pipeline` to inspect the data path. The two sources
feed `assemble`, then `order_state`. Open **Monitoring** to see the current
status and metrics; **Logs** shows recent pipeline messages.

In **Views**, open `order_state` and select **Documents** to browse a sample of
its stored documents.

[![Documents tab in the order_state view showing 5 sample rows and an assembled order document with shipments](/images/self-hosted/quickstart-view-documents.png)](/images/self-hosted/quickstart-view-documents.png)

To author your own pipeline files for a local or self-hosted server, see
[Create a workspace](/docs/overview/create-workspace) and
[Assemble documents with nest](/docs/guides/assemble-documents-with-nest).

## 4. Understand the result

The setup script checks the result in MongoDB (`views.order_state`) before printing the success line:
**5 orders and 6 embedded shipments**.

For order `1`, the sample result has this business shape (MongoDB's generated
`_id` is omitted):

```javascript
{
  id: 1,
  customer: "alice",
  amount: Decimal128("10.00"),
  shipments: [
    { id: 1, order_id: 1, carrier: "dhl", status: "delivered" },
    { id: 2, order_id: 1, carrier: "ups", status: "in_transit" }
  ]
}
```

The order fields come from MySQL; the `shipments` array comes from PostgreSQL.
The web application lets you inspect the pipeline, metrics, logs, and a sample
of stored documents. The setup script verifies the initial result directly in
MongoDB before reporting success.

## Connect your own AI agent

After confirming the initial result, you can connect an MCP-compatible AI agent
to build another pipeline in this disposable playground.

The v0.8 playground setup can generate `tapstate-demo/tapstate-mcp.json`. Check
that the file exists before configuring your agent. If the file is absent,
complete [manual MCP setup](/docs/reference/mcp#authenticate-the-host) and
enable [write tools](/docs/reference/mcp#write-tools) before asking an agent
to create or start a pipeline. The local data demo can succeed without this file.

The generated file contains a **write token** scoped to the playground. Keep it
private and out of version control. Connect only a host you trust to make
changes in this environment; do not give it your administrator password.

Install the tapstate authoring skills for your agent:

```bash
npx --yes skills add tapstate/tapstate-skills
```

When `tapstate-mcp.json` exists, launch an installed Claude Code client from
the `tapstate-demo` directory (if you used the saved-script steps above, you
are already in that directory):

```bash
claude --mcp-config tapstate-mcp.json
```

For another MCP host, add the file's `tapstate` server entry to its local MCP
settings, keeping its executable path, environment, and arguments together. The
JAR gateway needs Java 21 or newer; a script-generated Docker fallback needs
Docker running. See [MCP integration](/docs/reference/mcp#use-the-playground-configuration).

For example, ask:

> Create a separate pipeline named shipment_status_pipeline that keeps a live
> copy of fulfillment_db.shipments with only id, carrier, and status in a new
> shipment_status view. Preserve order_pipeline. Show me the proposed changes
> before applying them, then start the new pipeline and verify its stored rows.

Inspect proposed resource names and mappings before approving changes. Confirm
six initial shipment records and compare actual field values with the source.
An agent response or `RUNNING` status alone does not confirm correct output;
test controlled source inserts, updates, and deletes as shown in
[Explore the order-state demo](/docs/overview/order-state-demo).

## Keep, stop, or remove the playground

Keep the playground running while you explore the order-state demo or prepare
a workspace for your own [MySQL](/docs/connectors/mysql) or
[PostgreSQL](/docs/connectors/postgresql) source. Confirm that the tapstate
server can reach the database before applying it. This remains a disposable
evaluation environment; use sample or non-sensitive data only.

To pause it and preserve the sample data for later, run this from
`tapstate-demo`:

```bash
docker compose stop
```

Resume the same environment later with `docker compose start`.

When you no longer need the playground, remove its container data and start
clean next time:

```bash
docker compose down -v
```

This permanently removes the sample MySQL, PostgreSQL, and MongoDB volumes. It
does not remove the files or downloaded images.
