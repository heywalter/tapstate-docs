Try tapstate with sample data in a disposable local environment. The playground
starts MySQL, MongoDB, and a tapstate server, then guides you through an initial
snapshot and later changes captured with CDC.

This environment is for exploration. It is not a tapstate server installation
or deployment method, and it does not establish a production topology,
durability guarantee, or support contract for other connector combinations.

## What you'll explore

The guided flow lets you:

1. Start tapstate and two sample databases.
2. Use the CLI to connect, sign in, and register connectors.
3. Apply a MySQL source, a MongoDB target, and a pipeline.
4. Load the initial MySQL rows into MongoDB.
5. Watch inserts, updates, and deletes move through CDC.
6. Inspect pipeline status, metrics, logs, and target data.

## Before you begin

You need:

- macOS or Linux;
- Docker with the Compose plugin;
- `curl`;
- several GB of free Docker storage for the server and database images, connector
  JARs, and initialized volumes. Check it with `docker system df` and `df -h`.

You do not need to [install the tapstate CLI](/docs/overview/install) first.
The script downloads a local `v0.2.0` CLI and the two connector preview JARs
into the playground directory. Docker Compose runs the pinned
`ghcr.io/tapstate/tapstate:0.2.0` server image. The CLI stays in the playground
directory and is not added to your `PATH`.

## 1. Start the local environment

Use a new, empty directory and run the published playground script:

```bash
curl -fsSL https://install.tapstate.dev | sh
```

The root `install.tapstate.dev` URL is the playground entry point. It creates
and works inside a disposable `tapstate-demo` directory, installs the CLI in
that directory, and starts the Docker Compose stack. It does not install the
CLI globally. To inspect the script first, use:

```bash
mkdir tapstate-demo
cd tapstate-demo
curl -fsSL https://install.tapstate.dev -o quickstart.sh
less quickstart.sh
sh quickstart.sh
```

The script creates a local administrator, registers the MySQL and MongoDB
connectors, applies the MySQL source, discovers its schema, applies the full
workspace, starts `sync_orders`, and waits for the initial snapshot.

The published Compose mapping exposes the playground server at
`http://127.0.0.1:8080`. Use that literal address at the CLI REPL prompt; the
REPL does not expand shell variables such as `$TAPSTATE_URL`.

## 2. Confirm the initial snapshot

The script verifies the initial snapshot before it finishes. Confirm this
result before changing the sample data:

```text
quickstart: the target now holds 5 rows (MySQL orders -> MongoDB warehouse.orders)
```

The generated `.env` file contains the local playground password. Keep it local
and do not commit it.

## 3. Explore the running data path

Start an interactive CLI session from the playground directory:

```bash
./tapstate -w work
```

At the `tapstate>` prompt, connect to the local server and sign in:

```text
connect http://127.0.0.1:8080
login admin
```

Enter the password from `.env` when prompted. Then inspect the pipeline:

```text
status sync_orders --watch
```

Press <kbd>Ctrl</kbd>+<kbd>C</kbd> to stop watching without stopping the pipeline. You can also inspect metrics and recent node-local logs:

```text
metrics sync_orders
logs sync_orders
```

## 4. Experiment with CDC

With the five initial rows in MongoDB, open a second terminal in the playground
directory and change the sample data in MySQL:

```bash
docker compose exec mysql mysql -uroot -psecret appdb \
  -e "INSERT INTO orders VALUES (6, 'frank', 60.00);"

until docker compose exec -T mongo mongosh --quiet \
  'mongodb://mongo:27017/warehouse?directConnection=true' \
  --eval 'quit(db.orders.countDocuments({id:6})?0:1)'; do sleep 1; done

docker compose exec mysql mysql -uroot -psecret appdb \
  -e "UPDATE orders SET customer='franky' WHERE id=6;"

until docker compose exec -T mongo mongosh --quiet \
  'mongodb://mongo:27017/warehouse?directConnection=true' \
  --eval 'quit((db.orders.findOne({id:6})||{}).customer_name=="franky"?0:1)'; do sleep 1; done
```

Inspect the mapped document:

```bash
docker compose exec mongo mongosh --quiet \
  'mongodb://mongo:27017/warehouse?directConnection=true' \
  --eval 'db.orders.find({id:6}).pretty()'
```

Then delete it and wait until the target document is gone:

```bash
docker compose exec mysql mysql -uroot -psecret appdb \
  -e "DELETE FROM orders WHERE id=6;"

until docker compose exec -T mongo mongosh --quiet \
  'mongodb://mongo:27017/warehouse?directConnection=true' \
  --eval 'quit(db.orders.countDocuments({id:6})?1:0)'; do sleep 1; done
```

The insert creates the document, the update changes the mapped `customer_name` to `franky`, and the delete removes it.

## What gets created

The playground keeps all generated files in its directory:

```text
tapstate-demo/
├── .env
├── docker-compose.yml
├── mongodb-connector.jar
├── mysql-connector.jar
├── tapstate
└── work/
    ├── pipeline/
    └── source/
```

The workspace declares:

- a MySQL source using `mode: cdc`;
- a MongoDB target connection;
- a pipeline using `settings.read_mode: snapshot_and_cdc` that maps
  `appdb.orders` to `warehouse.orders`.

The connector JARs come from the separate [connector preview assets](https://github.com/tapstate/tapstate/releases/tag/connectors-preview).
They are provided for this local playground; the asset bundle is not a general
connector distribution or support matrix.

## Reset the environment

Pause the environment while keeping its data:

```bash
docker compose stop
```

Reset the environment before trying the flow again from clean databases:

```bash
docker compose down -v
```

The reset removes the playground's MySQL and MongoDB data. It does not remove
downloaded container images or files in `tapstate-demo`.

Run `sh quickstart.sh` from the playground directory to start the flow again.
