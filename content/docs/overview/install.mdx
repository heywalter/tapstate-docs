The current preview provides native tapstate CLI archives for macOS and Linux. The CLI installer is separate from the local Docker playground, so choose the path that matches what you want to do.

This page installs the CLI only. It does not install or start a tapstate server,
open a local port, or install connector JARs.

If you want to explore the complete MySQL-to-MongoDB flow instead, use [Try
tapstate locally](/docs/overview/quickstart-online). Its convenience command is
`curl -fsSL https://install.tapstate.dev | sh`; that root URL runs the disposable
Docker playground and does not add `tapstate` to your shell `PATH`.

## Understand the CLI and server

The CLI is useful on its own for authoring and validating local workspaces:

```text
new · validate · explain · ls · desc
```

A tapstate server is a separate, headless service. It has no built-in web UI in
`v0.2.0`; it exposes an authenticated control plane and runs pipelines. The
following operations require the CLI to connect to a running server:

```text
apply · register · test · discover-schema · start · status · metrics · logs
```

[Try tapstate locally](/docs/overview/quickstart-online) in a separate,
disposable environment. The demo downloads its own CLI and starts a server and
sample databases with Docker Compose. You do not need to install the CLI first.

Installing the CLI is enough for the offline authoring walkthrough, but it
cannot test a database connection or move data without a server.

## Supported platforms

| Operating system | Architecture | Recommended minimum |
|---|---|---|
| macOS | Apple silicon (`arm64`) | macOS 15.0 |
| macOS | Intel (`x64`) | macOS 15.0 |
| Linux with glibc | `arm64` | glibc 2.34 |
| Linux with glibc | `x64` | glibc 2.34 |

On macOS, the installer warns but does not stop when the version is older than the recommended minimum. On Linux, verify that your system uses glibc 2.34 or later. Alpine Linux and other musl-based distributions are not supported by the published binaries. On Windows, use WSL 2 or build from source.

## Install the CLI

Choose your platform, then run the CLI installer. The `/cli` endpoint serves the
current pinned preview installer; the installer selects the matching archive and
verifies its checksum before placing the binary.

The CLI installation has two network requests: the `/cli` endpoint returns the
installer script, then the script downloads the platform archive and its
published SHA-256 checksum from the GitHub release. The installer:

- selects the archive for your operating system and architecture;
- uses the pinned preview release unless `TAPSTATE_VERSION` overrides it;
- verifies its SHA-256 checksum;
- installs `tapstate` in `$HOME/.tapstate/bin` by default;
- does not use `sudo` or edit your shell profile.

It should finish with a message similar to:

```text
tapstate 0.2.0 installed to <home>/.tapstate/bin/tapstate
```

Add the installation directory to `PATH` if it is not already available:

```bash
export PATH="$HOME/.tapstate/bin:$PATH"
```

To keep the setting for future Zsh sessions:

```bash
printf '%s\n' 'export PATH="$HOME/.tapstate/bin:$PATH"' >> "$HOME/.zshrc"
```

Verify the result:

```bash
tapstate --version
```

The command should report `tapstate 0.2.0`.

If Zsh reports `command not found: tapstate`, either the installer did not
finish or its default directory is not on the current shell's `PATH`. Check the
installed file first:

```bash
test -x "$HOME/.tapstate/bin/tapstate" && "$HOME/.tapstate/bin/tapstate" --version
```

If that succeeds, run the `export PATH=...` command above for the current
shell. After adding it to `.zshrc`, open a new terminal or run `source
"$HOME/.zshrc"`, then repeat `tapstate --version`.

## Audit, pin, or mirror the installer

The one-line command is convenient, but it executes a remote script. To inspect
the exact script before running it, download it first:

```bash
curl -fsSL https://install.tapstate.dev/cli -o install-tapstate.sh
less install-tapstate.sh
sh install-tapstate.sh
```

To pin the preview explicitly, set `TAPSTATE_VERSION` when running the saved
script:

```bash
TAPSTATE_VERSION=0.2.0 sh install-tapstate.sh
```

If GitHub release downloads are restricted or slow in your network, use a
mirror that preserves the release layout expected by the installer:

```bash
TAPSTATE_BASE_URL="https://mirror.example.com/tapstate/releases" \
TAPSTATE_VERSION=0.2.0 \
sh install-tapstate.sh
```

The mirror must provide
`download/v<version>/tapstate-<version>-<os>-<arch>.tar.gz`, its `.sha256`
file, and `platform-minimums.txt`.

## Other installation methods

### Use a different installation directory

Set `TAPSTATE_INSTALL_DIR` before running the installer:

```bash
TAPSTATE_VERSION=0.2.0 \
TAPSTATE_INSTALL_DIR="$HOME/bin" \
sh install-tapstate.sh
```

The selected directory must be on your `PATH` before you can invoke `tapstate` by name.

### Install manually

The [v0.2.0 release](https://github.com/tapstate/tapstate/releases/tag/v0.2.0) includes four platform archives, individual `.sha256` files, and a combined `checksums.txt`. Download the archive that matches your system and verify its checksum before extracting it.

For example, on Apple silicon:

```bash
curl -fLO \
  https://github.com/tapstate/tapstate/releases/download/v0.2.0/tapstate-0.2.0-darwin-arm64.tar.gz
curl -fLO \
  https://github.com/tapstate/tapstate/releases/download/v0.2.0/tapstate-0.2.0-darwin-arm64.tar.gz.sha256

shasum -a 256 -c tapstate-0.2.0-darwin-arm64.tar.gz.sha256
tar -xzf tapstate-0.2.0-darwin-arm64.tar.gz
```

The archive extracts a complete `tapstate-cli-0.2.0` bundle. Keep its `bin` and
`libexec` directories together so `tapstate mcp` can find its sidecar.

If macOS blocks a manually downloaded binary after the checksum passes, remove the quarantine attribute and try again:

```bash
xattr -d com.apple.quarantine ./tapstate-cli-0.2.0/bin/tapstate
./tapstate-cli-0.2.0/bin/tapstate --version
```

### Update or remove the CLI

The preview has no automatic updater. To install a later release, rerun the
installer with its version pinned and verify the reported version.

To remove the default installation, including versioned bundles and the MCP
sidecar:

```bash
rm -rf "$HOME/.tapstate"
```

Workspaces, containers, and external-system data are separate and are not removed.

## Optional integrations

### Connect an MCP host

The full CLI bundle includes `tapstate mcp`, a local gateway for MCP-compatible
AI tools. It does not start a tapstate server or provide an interactive prompt.
Use it only when a server is already running and you have its
`TAPSTATE_TOKEN`; the gateway also requires Java 21 or newer. Offline CLI
commands do not require Java. See the [CLI reference](/docs/reference/cli#mcp)
for the host configuration and command example.

## Next steps

Before evaluating the runtime, account for two known `v0.2.0` limitations:

- An insert-only target can receive duplicate rows when the snapshot and CDC
  reads overlap. A change that the connector reads is delivered at least once,
  not exactly once.
- A source change written while the change stream is positioning itself can be
  missed before the connector reads it, because the saved position is not
  handed to the stream read until the snapshot finishes.

See the [v0.2.0 release](https://github.com/tapstate/tapstate/releases/tag/v0.2.0)
for the published disclosure.

- [Author and validate a workspace](/docs/overview/quickstart) using only the installed CLI.
- If Docker is available, [try tapstate locally](/docs/overview/quickstart-online) with the disposable MySQL-to-MongoDB demo.
