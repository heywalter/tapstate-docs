## Try the current preview

The [Quickstart](/docs/quickstart) uses supplied MySQL and PostgreSQL samples
and your Atlas storage. Choose a sample to run an Order 360 pipeline. Then
[build a pipeline](/docs/guides/build-a-pipeline) with your own databases to
replicate tables, transform records, or assemble documents in Atlas.

For a disposable environment with databases included, use the
[local quickstart](/docs/overview/quickstart) or
[local order-state demo](/docs/overview/order-state-demo) to run MySQL,
PostgreSQL, MongoDB, and tapstate in Docker. See
[Self-hosting](/docs/self-hosted) for the distinction between this playground,
the CLI client, and server configuration.

## Developers and AI agents

For assistance inside Cloud, use [Build with AI](/docs/guides/build-a-pipeline#build-with-ai).
The [CLI](/docs/overview/install) and [MCP](/docs/reference/mcp) guides cover
local clients and self-hosted authentication; they do not sign an agent into
your Cloud account. Use the [REST API](/docs/reference/rest-api) only with its
documented deployment-specific authentication.

[Create a workspace](/docs/overview/create-workspace) when you need reviewable
`.tap.yml` files in version control. Match its fields to your server's schema;
the Cloud reference can include fields absent from older CLI versions (such as v0.7) or a server on another release.
