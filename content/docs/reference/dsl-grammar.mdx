Tapstate resources are YAML files named `*.tap.yml`. Each file contains one
`version: tapstate/v1` resource.

Use the Schema and connector catalog bundled with the same tapstate version as
your CLI. This site does not yet publish a stable, versioned Schema URL.

## Workspace layout

The canonical workspace layout groups files by resource kind:

```text
tap-work/
├── source/
├── pipeline/
├── transform/
├── view/
└── serve/
```

`tapstate new` writes `<workspace>/<kind>/<id>.tap.yml`. `tapstate validate`
accepts a workspace directory or one resource file.

## Resource kinds

| Kind | Declares |
|---|---|
| [`source`](/docs/reference/source) | A connector connection. A read source includes `mode`; a target connection omits it. |
| [`pipeline`](/docs/reference/pipeline) | Source references, ordered transform steps, an optional view, a serve surface, and task settings. |
| [`transform`](/docs/reference/transforms) | Reusable transform logic without input wiring. |
| [`view`](/docs/reference/view-and-serve) | Reusable materialization settings without input wiring. |
| [`serve`](/docs/reference/view-and-serve) | Reusable `sync`, `query`, and `push` declarations without input wiring. |

A string reference resolves by resource ID. Top-level IDs must be unique in the
workspace and cannot contain `.`.

## Minimal runnable shape

The released preview path uses two connection resources and one pipeline:

```yaml title="source/orders.tap.yml"
version: tapstate/v1
kind: source
id: orders
connector: mysql
mode: cdc
config:
  host: mysql
  port: "3306"
  database: appdb
  username: ${MYSQL_USER}
  password: ${MYSQL_PASSWORD}
tables: [orders]
```

```yaml title="source/warehouse.tap.yml"
version: tapstate/v1
kind: source
id: warehouse
connector: mongodb
config:
  isUri: true
  uri: ${MONGODB_URI}
```

```yaml title="pipeline/orders-sync.tap.yml"
version: tapstate/v1
kind: pipeline
id: orders-sync
source: orders
settings:
  read_mode: snapshot_and_cdc
serve:
  from: orders
  sync:
    - source: warehouse
```

Apply the two connection resources first, run `discover-schema orders`, then
apply the complete workspace and start the pipeline. Add expressions that read
`after.<field>` or `before.<field>` only after discovery has supplied the field
types used during server-side validation.

For the complete field shapes, see [source](/docs/reference/source),
[pipeline](/docs/reference/pipeline), [transforms](/docs/reference/transforms),
and [view and serve](/docs/reference/view-and-serve).

## Declaration and execution are different checks

The v1 Schema describes what can be declared. The current preview runtime
executes a smaller subset.

| Surface | Schema/validator | Current preview runtime |
|---|---|---|
| Resource kinds | `source`, `pipeline`, `transform`, `view`, `serve` | The local playground declares `source` + `pipeline` with inline `serve.sync`. |
| Transforms | `filter`, `map`, `js`, `union`, `nest`, `join` | `filter`, `map`, `js`, `union`, and `nest` are wired. The runtime refuses `join`. |
| Serve declarations | `sync`, `query`, `push` | The local playground exercises `sync`. Do not infer an executable runtime surface from Schema acceptance alone. |
| Connector fields | Connector-specific keys are allowed structurally; known catalog fields can receive additional checks. | A catalog entry does not prove that a connector artifact is installed, registered, or release-verified. |

## Validation model

Offline validation checks:

1. YAML and Schema structure;
2. cross-file ID and reference closure;
3. rules exposed by the bundled connector catalog.

Validation does **not** connect to an external system, verify credentials or
network access, install a connector artifact, or prove that a Schema-declared
feature is executable by the current runtime. Unknown connector-specific config
keys can pass the current offline validator, so test the real connector path
before relying on a configuration.

## Quote regular-expression table selectors

Quote a table-selector regex when it contains YAML flow indicators such as `?`
or `:`. This includes negative lookahead expressions:

```yaml
tables:
  - "/^(?!timezone_test$).*/"
```

The equivalent flow form is `tables: ["/^(?!timezone_test$).*/"]`. Keeping the
regex quoted preserves it as one string and ensures that canonical YAML returned
by tapstate remains parseable. Do not rely on an unquoted scalar for these
patterns, even if a YAML parser happens to accept the input form.

## Compatibility rules

- Unknown top-level fields are rejected.
- Connector-owned `config`, `options`, and `experimental` maps can accept
  extension fields.
- `experimental` fields do not carry the v1 compatibility guarantee.
- Use the Schema and catalog from the same release as the runtime you deploy.

To explore a running example, [try tapstate locally](/docs/overview/quickstart-online).
For connector metadata and external-system preparation, use the
[connector directory](/docs/connectors).
