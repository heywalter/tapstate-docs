Use these guides to prepare database permissions, authentication, network
access, and capture settings, then add the connection in your Cloud Cluster.

Start with the [Quickstart](/docs/quickstart) to explore supplied sample
databases and Atlas storage, or follow [Build a pipeline](/docs/guides/build-a-pipeline)
to connect your own database tables. For self-hosted servers, also see
[Register and test connectors](/docs/guides/register-connectors).

## Supported connectors

These seven guides cover the published connector catalog: six guides cover the
eight connector IDs in the standard Cloud distribution (MySQL includes RDS
preparation, and MongoDB covers both MongoDB and Atlas destinations), and
[Db2 for i](/docs/connectors/db2i) (`db2i`) is a source-only Preview that
requires separate [connector registration](/docs/guides/register-connectors)
before use.

<ConnectorDirectoryMatrix />

**Guide maturity** indicates the stability of each guide and its configuration
contract (`GA` vs `Preview`), not a production SLA for the Cloud Preview runtime.
Validate your specific database version, edition, and data types against a
non-production workload before relying on a path, and review
[Preview limits](/docs/limits). Before testing connectivity, allow the
[Cluster's outbound address](/docs/manage/clusters#prepare-network-access)
through your database firewall. Snapshot-only reads do not require database CDC
logging ([Capture modes](/docs/concepts/capture-modes)). A shared creation form
may display **Read mode** on a destination connection, which does not extend its
Cloud role; connector availability in an existing Cluster also depends on its
deployed distribution.

## Managed database services

| Service | Cloud scope |
| --- | --- |
| Amazon RDS for MySQL | Source-only Preview through `aws-rds-mysql`. Follow the [MySQL source prerequisites](/docs/connectors/mysql#source) and configure RDS binlog retention with `mysql.rds_set_configuration`. Confirm your RDS engine version and parameter group settings before use. |
| Amazon RDS for PostgreSQL, Oracle, or SQL Server | Confirm the exact managed service with support before use. The base database guide is not a managed-service compatibility guarantee. |
| Azure SQL Database and Azure SQL Managed Instance | Outside the standard Cloud connector set. Self-managed SQL Server compatibility does not extend to these managed services. |

For a compatibility request, include the provider, database product, version,
edition, and required read mode. Do not include credentials.

## Connection workflow

1. Check [Supported connectors](#supported-connectors) and complete your
   database guide’s prerequisites, including the Cluster’s network access,
   database permissions, and CDC configuration.
2. In your Cluster, open **Data Sources** > **Create source** and select the
   connector. **Overview** > **Add Databases** provides another entry point.
3. Use the guide’s **Connection settings** section: screenshot first, then
   required and advanced fields. Run **Test connection**, resolve failed checks,
   and select **Create source**.
4. Open the source and check its discovered tables and keys. You can now
   [build a pipeline](/docs/guides/build-a-pipeline#2-create-a-draft) using them.

See [Manage data sources](/docs/guides/manage-data-sources) for TLS and SSH
settings, later connection tests, edits, and schema refresh. Adding a connection
makes its tables available to the builder; a pipeline controls which data is read
and how it is written to Atlas.

## Self-hosted servers

Cloud Clusters stage a fixed connector set automatically. Self-hosted server
containers (`ghcr.io/tapstate/tapstate:0.8.0`) and standalone binary or JAR
deployments start without bundled connector JARs—mount verified connector
artifacts in `/var/lib/tapstate/connectors` (`TAPSTATE_CONNECTORS_SEED_DIR`,
including `mongodb` for the default `views` store) or register them explicitly
(including Preview connectors such as `db2i`); see
[Register and test connectors](/docs/guides/register-connectors).
