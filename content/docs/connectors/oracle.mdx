Connect Oracle as a source for an initial full load and redo-log CDC into
operational state or analytics targets. Complete the database preparation that matches the
read mode you plan to use.

For Cloud version and deployment scope, check [Supported connectors](/docs/connectors#supported-connectors).
Already prepared the database? [Connect it in the Web application](#connect-to-oracle).

## Before you begin

In Cloud, select the connector in **Data Sources**. Check
[Supported connectors](/docs/connectors#supported-connectors) for the version and deployment
scope, then allow the [Cluster's outbound address](/docs/manage/clusters#prepare-network-access)
through the database's firewall. Complete the read-mode preparation below
before selecting **Test connection**.

Connector registration and host-level setup in this guide apply to self-hosted
servers.

<span id="source" />

Prepare the database for the source read mode you plan to use.

Choose the outcome you need. Each tab is a complete preparation path; you do not need to combine steps from both tabs.

<SourceModeTabs label="Choose the Oracle source read mode">
<SourceModeTab value="snapshot" label="Full load (Snapshot)" description="Copy existing rows once">

Use **Full load** (`Snapshot`) to copy the rows that exist now. It does not require ARCHIVELOG, supplemental logging, or LogMiner.

**1. Create a dedicated reader**

Create a dedicated account in the database or pluggable database that contains the source objects:

```sql
CREATE USER tapstate IDENTIFIED BY "replace-with-a-secret";
GRANT CREATE SESSION TO tapstate;
GRANT SELECT ON V_$DATABASE TO tapstate;
```

For a common user in a multitenant database, switch to `CDB$ROOT`, use the required common-user prefix such as `C##`, and specify the appropriate container scope. Confirm whether one tapstate connection represents a single PDB or a common account before granting `CONTAINER=ALL`.

**2. Grant read access to the selected objects**

Use narrowly scoped object grants where possible; `SELECT ANY TABLE` is broader:

```sql
GRANT SELECT ON app_schema.orders TO tapstate;
GRANT SELECT ON app_schema.customers TO tapstate;
```

</SourceModeTab>
<SourceModeTab value="snapshot-cdc" label="Full load + CDC" description="Copy existing rows, then follow redo changes">

Use this preparation path when the destination must begin with existing rows, then capture ongoing redo changes.

Tapstate uses **Oracle LogMiner** as its primary CDC engine. LogMiner decodes committed transactions directly from Oracle online redo logs and archived redo logs through standard JDBC using built-in database packages (`DBMS_LOGMNR`), without requiring external binaries or host agents. Complete the database preparation below to enable LogMiner access:

**1. Create a reader with snapshot and mining access**

Create the account in the database or PDB that contains the source objects, grant `SELECT` on the selected tables, and grant the data-dictionary and transaction access used by LogMiner:

```sql
CREATE USER tapstate IDENTIFIED BY "replace-with-a-secret";

GRANT CREATE SESSION,
      ALTER SESSION,
      EXECUTE_CATALOG_ROLE,
      SELECT ANY DICTIONARY,
      SELECT ANY TRANSACTION,
      SELECT ANY TABLE
TO tapstate;

GRANT SELECT ON V_$DATABASE TO tapstate;

-- Oracle 12c and later
GRANT LOGMINING TO tapstate;
```

On Oracle 11g, grant `EXECUTE ON DBMS_LOGMNR` and `SELECT ON V_$LOGMNR_CONTENTS` instead of `LOGMINING`.

**2. Enable archive logging**

LogMiner reads from archived redo logs. Confirm archive-log mode is active:

```sql
SELECT LOG_MODE FROM V$DATABASE;
```

If it returns `NOARCHIVELOG`, configure archive logging in a maintenance window:

```sql
SHUTDOWN IMMEDIATE;
STARTUP MOUNT;
ALTER DATABASE ARCHIVELOG;
ALTER DATABASE OPEN;
```

**3. Enable supplemental logging**

Supplemental logging ensures that redo logs contain the columns needed to reconstruct update and delete events.

```sql
-- Minimal supplemental logging at database level:
ALTER DATABASE ADD SUPPLEMENTAL LOG DATA;

-- Identification logging on replicated tables:
ALTER TABLE app_schema.orders
  ADD SUPPLEMENTAL LOG DATA (ALL) COLUMNS;

ALTER SYSTEM SWITCH LOGFILE;
```

For a PDB, run `ALTER SESSION SET CONTAINER=PDB_name;` before applying table-level logging.

</SourceModeTab>
</SourceModeTabs>

## Connect to Oracle

1. Open your Cluster and select **Data Sources** > **Create source**.
2. Select **Oracle** and enter a **Source ID**.
3. Choose the read mode you prepared, then enter the connection settings below.

   <span id="reference" />
   <span id="connection-settings" />

   [![Oracle connection form populated with example settings](/images/cloud/oracle-form.png)](/images/cloud/oracle-form.png)

   The screenshots use fictional connection details. Replace them with your own.
   The settings below include fields outside the captured area and options
   shown only for particular connection modes.
   Configuration keys are included for the alternative CLI/YAML workflow.

   - **Connection settings**

     - **Source ID (`id`)**: A stable ID for the connection, such as `orders_oracle`. It cannot be renamed after creation. Required.
     - **Read mode (`mode`)**: `snapshot` for a one-time read, or `cdc` for existing rows and later changes. Complete the matching preparation above. Select before creation.
     - **Connection mode (`thinType`)**: Oracle connection addressing mode: `SID` or `SERVICE_NAME`. Default: `SID`. Required.
     - **DB Address (`host`)**: Oracle database host address or hostname. Required when Connection mode is `SID`, `SERVICE_NAME`.
     - **Port (`port`)**: Oracle listener port. Use a numeric integer. Default: `1521`. Required when Connection mode is `SID`, `SERVICE_NAME`.
     - **SID (`sid`)**: Oracle system identifier (SID). Required when Connection mode is `SID`.
     - **Service Name (`database`)**: Oracle service name. Required when Connection mode is `SERVICE_NAME`.
     - **Schema (`schema`)**: Oracle schema containing the source tables. Required.
     - **`user`**: Database account username (also accepted as `username`).
     - **`password`**: Database account password or secret reference.
     - **`logPluginName`**: Incremental CDC capture engine: `logMiner` or `oracle-log-parser`. Default: `logMiner`. Optional.
     - **Multi-tenant (`multiTenant`)**: Set to `true` when connecting to a multitenant database (CDB/PDB). Optional.
     - **PDB (`pdb`)**: Pluggable database (PDB) name. Required when Multi-tenant is `true`.

   - **Advanced settings**

     - **Timezone for Datetime (`timezone`)**: Timezone offset for temporal conversions (e.g. `+00:00`, `+08:00`). Optional.
     - **grpc server host (`rawLogServerHost`)**: Helper gRPC server host for the raw-log parsing path. Optional.
     - **grpc server port (`rawLogServerPort`)**: Helper gRPC server port for raw-log parsing (defaults to `8190`). Default: `8190`. Optional.
     - **Read log from slave (`standBy`)**: Whether to read logs from a standby or replica node (defaults to `false`). Default: `false`. Optional.
     - **Connection String Params (`extParams`)**: Additional JDBC connection parameters appended to the connection string. Optional.
     - **Load Table Comment (`loadTableComment`)**: Whether to discover and load table comments (defaults to `false`). Default: `false`. Optional.
     - **Use SSL (`useSSL`)**: Whether to enable SSL/TLS encryption (defaults to `false`). Default: `false`. Optional.
     - **SSL Certificate(PEM) (`sslCert`)**: PEM-encoded SSL certificate when `useSSL` is enabled. Required when Use SSL is `true`.
     - **SSL Certificate Password (`sslKeyPassword`)**: Secret password protecting the SSL certificate. Required when Use SSL is `true`.
     - **Socket ReadTimeOut (minutes) (`socketReadTimeOut`)**: Socket read timeout in minutes (defaults to `0`, meaning no timeout). Default: `0`. Optional.

   - **Connection security**: Use the TLS and SSH settings offered by the connector.
     See the [shared transport fields](/docs/guides/manage-data-sources#tls-and-ssh-connections)
     for certificate files and SSH account settings. Keep certificate verification enabled.

   Advanced capture settings require their corresponding database and runtime
   preparation; selecting a different log reader does not install it.

   Oracle Free 23 requires `autoLog: false` for CDC. If your form does not expose
   automatic continuous log mining, ask support to confirm this setting before
   starting CDC. See [additional configuration](#additional-configuration).

## CLI and YAML

This alternative is for **self-hosted servers**. File generation and validation
can run offline; login, apply, and connection tests require your own server.
Cloud users should use the Web steps above. See [CLI scope](/docs/self-hosted#cli-and-automation).

Use the same [connection settings](#connection-settings) as the Web form.
In YAML, put connector-specific keys under `config`; `id` and `mode` are resource fields.

### Register on a self-hosted server

<span id="connector-availability-and-licensing" />

The Oracle connector artifact bundles `ojdbc8`, `orai18n`, and `xdb` under the Oracle Free Use Terms; commercial connector use remains subject to the applicable agreement. It is distributed as an official preview artifact separate from the base server image. Before applying Oracle connections on a new or upgraded server, register the connector:

```text
connectors
register oracle
```

In production and air-gapped environments, you can also mount the connector JAR into `TAPSTATE_CONNECTORS_SEED_DIR` for automatic boot-time registration. See [When registration is required](/docs/guides/register-connectors#when-registration-is-required).

### Create a connection

Use this alternative when authoring a local workspace. For browser setup,
complete the connection flow above; no local file is required.

Tapstate stores each Oracle connection as a `.tap.yml` file in the workspace.

Create `tapstate-work/source/orders_oracle.tap.yml`. For a full-load-only source, use `mode: snapshot`; for CDC, use `mode: cdc`.

```yaml title="tapstate-work/source/orders_oracle.tap.yml"
version: tapstate/v1
kind: source
id: orders_oracle
connector: oracle
config:
  host: oracle.internal
  port: 1521
  thinType: SERVICE_NAME
  database: ${ORACLE_SERVICE_NAME}
  schema: APP_SCHEMA
  user: ${ORACLE_READER_USER}
  password: ${ORACLE_READER_PASSWORD}
mode: cdc
tables:
  - ORDERS
  - /CUSTOMERS_.*/
```

For Oracle 23c (Free), set `autoLog: false` because the automatic miner requests
`CONTINUOUS_MINE`, which Oracle 23c no longer supports. Keep schema, table, and
column identifiers within 30 characters for this LogMiner path. A snapshot can
succeed while CDC cannot read changes for a longer identifier; tapstate does
not reject that configuration before capture starts.

Before using the pipeline below, add the `operational_state` target connection
from the [MongoDB guide](/docs/connectors/mongodb#create-a-connection) to the
same workspace. This pipeline assumes that target already exists:

```yaml title="tapstate-work/pipeline/orders_to_operational_state.tap.yml" structure-only
version: tapstate/v1
kind: pipeline
id: orders_to_operational_state
source: orders_oracle
serve:
  from: /.*/
  sync:
    - id: write_operational_state
      source: operational_state
      write_mode: upsert
      ddl: fail
```

This guide covers Oracle as a source. Cloud does not accept Oracle sync
targets. Self-hosted target allowances do not certify Oracle writes; see
[Registration and target boundaries](/docs/guides/register-connectors#current-preview-registration-boundary).

Use a staging schema to verify:

1. table discovery and a small snapshot;
2. an insert, update, and delete through CDC;
3. a log switch while the task is running;
4. restart from the saved redo position;
5. representative `NUMBER`, timestamp, LOB, and empty-string values.

These checks help confirm the database-side prerequisites without changing them:

```sql
SELECT LOG_MODE, SUPPLEMENTAL_LOG_DATA_MIN
FROM V$DATABASE;

SELECT DEST_NAME, STATUS, DESTINATION
FROM V$ARCHIVE_DEST_STATUS
WHERE STATUS <> 'INACTIVE';

SELECT RESOURCE_NAME, LIMIT
FROM DBA_PROFILES
WHERE PROFILE = (SELECT PROFILE FROM DBA_USERS WHERE USERNAME = 'TAPSTATE')
  AND RESOURCE_NAME = 'CONNECT_TIME';
```

## Limitations

- Keep LogMiner identifiers within 30 characters. Longer identifiers can fail CDC even after a successful snapshot, without a pre-start refusal.
- `INTERVAL` and `XMLTYPE` are not supported by the LogMiner baseline. The direct raw-log baseline does not support `TIMESTAMP WITH LOCAL TIME ZONE`.
- Oracle treats empty strings as `NULL`, so source `VARCHAR2` columns containing `''` arrive downstream as `null`.
- DDL and a large burst of DML on the same table can make dictionary reconstruction unreliable. Stage schema changes separately from heavy write windows when possible.
- RAC LogMiner capture can produce duplicate events during recovery. Downstream writes need stable keys and idempotent handling, especially for tables without primary keys.
- Oracle 19c LogMiner scans online redo together with archived logs. In RAC, it must follow multiple redo threads; large redo logs and uneven archiving can increase incremental-read latency.
- Large or long-running uncommitted transactions retain mining state. After a restart, recovery can resume from the earliest uncommitted SCN and replay already-seen events, so the destination must handle them idempotently.
- Virtual columns require staging with representative changes. If their incremental values cannot be reproduced reliably, pre-create the target shape or exclude the virtual expression from the replicated contract.
- Archive-log exhaustion stops recoverable CDC. Monitor the recovery area and long-running or uncommitted transactions.
- A restrictive profile `CONNECT_TIME` can terminate the mining session and interrupt CDC. Use a service-account profile that matches the pipeline's expected lifetime.
- Partition-table DML can be captured, but adding partitions is not part of the documented DDL baseline.
- Configure Oracle Net encryption according to your environment and use the connection settings supplied by your tapstate deployment.

## Troubleshooting

### ORA-01882 during login

If login fails with `ORA-01882: timezone region not found`, check the tapstate
server JVM's timezone. The Cloud runtime defaults to `UTC`, avoiding
an implicit `Etc/UTC` region that some Oracle configurations reject. An explicit
JVM `user.timezone` takes precedence; ask the server operator to inspect it.
Retest the connection after correcting the runtime setting.

The connector's `timezone` conversion offset is a separate setting. Changing it
is not a substitute for resolving an Oracle login timezone error.

## Data compatibility

### Database-side reference

This table summarizes Oracle behavior for the connector. Verify uncommon types
and deployment-specific capture paths with representative data before migration.

| Signal | Database-side baseline |
|---|---|
| Versions | Oracle 9i, 10g, 11g, 12c, 18c, 19c, 23c (Free) |
| Architectures | Single instance and RAC. The LogMiner baseline reads primary nodes in Data Guard, Active Data Guard, and ASM deployments; standby-node capture requires the separately supplied raw-log contract. |
| Source preparation | Snapshot and CDC prerequisites |
| DDL | Add, rename, alter, and drop columns |

### Data types

| Family | Database-side baseline |
|---|---|
| Text | `VARCHAR2`, `CHAR`, `NVARCHAR2`, `NCHAR`, `CLOB`, `NCLOB` |
| Numeric | `NUMBER`, `INTEGER`, `FLOAT`, `BINARY_FLOAT`, `BINARY_DOUBLE` |
| Date and time | `DATE`, `TIMESTAMP`, `TIMESTAMP WITH TIME ZONE`, `TIMESTAMP WITH LOCAL TIME ZONE`, `INTERVAL` |
| Other | `BLOB`, `XMLTYPE` |

Method-specific source exclusions are listed in [Limitations](#limitations).
